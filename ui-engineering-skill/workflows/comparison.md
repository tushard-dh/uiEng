# Comparison

When two or more references are selected:

1. Analyze each independently.
2. Normalize terminology.
3. Compare equivalent patterns.
4. Identify conflicts.
5. Identify strengths and weaknesses.
6. Consider product requirements.
7. Recommend a product-specific outcome.
8. Preserve provenance.

Compare dimensions such as:
- information architecture
- navigation
- layout
- density
- search
- filtering
- tables
- forms
- detail views
- actions
- states
- responsiveness
- accessibility

Do not average designs mechanically.

Example:

```text
Reference A:
- spacious cards
- strong visual hierarchy

Reference B:
- dense data table
- powerful filtering

Product:
- recruiter workflow with high record volume

Recommendation:
- use A's page hierarchy
- use B's table/filter pattern
- use internal design-system tokens
```
